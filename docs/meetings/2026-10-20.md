## 2. Agenda and discussion
1. **Brief and marking rubric.** Reviewed the deliverables: 6 private repositories (experiments, Streamlit, 4 APIs), Render and Streamlit Community Cloud deployments, the experiment notebook template, the group report, and the mandatory package versions (Python 3.12.13 and pinned libraries). Noted that 20 % of the marks depend on evidence of collaboration, so all decisions are minuted here.
2. **Roles and targets.** Each member owns one target, one API, one Streamlit page and a set of features that the others consume:
   - Student A: Asset Performance Index
   - Student B: Market Risk Index
   - Student C: Trend Category
   - Student D: Trading Opportunity Rating
3. **Data source.** Kraken public OHLC API (daily USD candles, last 720 complete days, no API key), used for both training and serving so that the deployed models see the same data definition as in training. The provided CoinMarketCap-format CSV is used only for exploratory comparison.
4. **Integration contract (CONTRACT.md v0.1, proposed by Student B).** The contract fixes:
   - the 8 supported tokens and the 7-day horizon
   - exact feature names and pandas formulas
   - the request and response JSON for `/`, `/health`, `/features`, `/predict` and `/model-metadata`
   - the brief's error format
   - resilience rules (timeouts, retries, NaN fallback)
   - modelling conventions (chronological split with 7-day purge gap, Optuna, baselines, metrics)
   - milestones
5. **Shared feature package.** Proposal to publish all feature and target code once, as `mykrml-25740287`, so every service computes identical features.
